> 原版仓库：[MeteorNOX/DeepSeek-Balance-Whale-Widget](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget)（MIT）
> 本插件 ID：`ZhinaiNai.WhaleWidget`

---

## 一、先分清层次（关键）

| 层 | 文件 | 上游更新时 |
|---|---|---|
| **原版源码** | `upstream/lib/index.js`、`upstream/assets/whale-widget.js`、`upstream/assets/*` | ⚠️ 会被覆盖，需重打补丁 |
| **宿主壳** | `host/server.mjs` | ✅ 独立文件，不受影响 |
| **窗口壳** | `host/window.py` | ✅ 独立文件，不受影响 |
| **Alife 插件壳** | `WhaleWidgetModule.cs`、`manifest.json` | ✅ 独立文件，不受影响 |

**结论：上游更新 → 覆盖 `upstream/` → 跑一次 `node tools/apply-patches.mjs` 即可。**

## 二、操作步骤

```bash
# 1) 备份当前的 upstream/（保险起见）
mv upstream upstream.bak-$(date +%Y%m%d)

# 2) 拉取上游新版
curl -L -o /tmp/upstream.zip \
  https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget/archive/refs/heads/main.zip
unzip -q /tmp/upstream.zip -d /tmp/
mv /tmp/DeepSeek-Balance-Whale-Widget-main upstream
rm -rf upstream/.github upstream/.gitattributes upstream/.gitignore

# 3) 重打补丁（锚点找不到会直接报错，不会静默跳过）
node tools/apply-patches.mjs

# 4) 语法自检
node --check upstream/lib/index.js
node --check upstream/assets/whale-widget.js

# 5) 确认补丁落点
grep -c "★ 移植补丁" upstream/lib/index.js upstream/assets/whale-widget.js

# 6) 冒烟：跑一次宿主，看路由数是否为 23
WHALE_SRC=$PWD/upstream WHALE_PORT=55321 timeout 10 node host/server.mjs
```

期望输出包含：

```
[whale-host] 原版插件已加载，路由数: 23
```

路由数变了说明上游改了接口，需要进一步排查（见第四节）。

## 三、补丁清单（共 7 处）

补丁全部在 `tools/apply-patches.mjs` 里，带 `★ 移植补丁` 注释便于搜索定位。

### `upstream/lib/index.js`（2 处）

在 `let CUSTOM_PRICES = {}` 之前插入 `refreshLocalPricing()`（读 Alife 侧定价文件），
并在 `function priceFor(model)` 开头调用它。

> 💡 若嫌麻烦可以去掉这两处 —— 原版内置价目表本身就是对的，
> 保留只是为了「你在用量看板里调价，挂件自动跟随」。

### `upstream/assets/whale-widget.js`（5 处）

| # | 位置 | 改动 |
|---|---|---|
| 3 | 厂商模板循环 | `if (apiTemplates[ti].builtin) continue` → `... && isNew) continue` |
| 4 | `var tplSel = apiSelectEl(...)` 之后 | 当前 provider 不在候选里时补一项并重设值 |
| 5 | `collect()` 里 | `provider: isNew ? tplSel.value : ((m && m.provider) || tplSel.value)` |
| 6 | `onDocPointerMove` 里 | `state.top = drag.origTop` |
| 7 | `endDrag` 里 | `var top = drag.origTop` |

3–5 修的是「编辑内置模型保存报『未知的厂商模板』」；
6–7 是「竖直锁定」，让挂件只做水平拖拽 —— 竖直位置不动，窗口就不跟着跑，
设置弹窗永远有空间展开。

### `host/window.py`（本移植新写，非补丁）

自包含了原版调试期打的两处**运行时**补丁，所以不需要再改 `webview/platforms/winforms.py`：

- **透明**：窗体 `BackColor=Black` + `DwmExtendFrameIntoClientArea(hwnd, -1)`。
  `pywebview` 的 `transparent=True` 只把 WebView2 背景设为透明，下层 WinForms 窗体底色
  （默认 `#F0F0F0` 浅灰）照样显示 → 屏幕上会多一块灰板。
  备选方案均已排除：`LWA_COLORKEY` 无效（WebView2 不吃色键）；
  `TransparencyKey` 能透明但该色区域整窗 hit-test 穿透（点不动、拖不动）。
- **区域裁剪**：`SetWindowRgn` 把窗口限制为「挂件本体 ∪ 可见浮层」，其余透明区穿透到桌面。
  区域坐标要乘 `devicePixelRatio`（`evaluate_js` 给 CSS 像素，`SetWindowRgn` 要物理像素）。

## 四、风险提示

- **上游大改架构**（换导出方式、改服务依赖、加新 `ctx.xxx` 接口）时，
  `host/server.mjs` 可能也要跟着适配，不只是打补丁。
  判断信号：路由数变化，或加载时报 `ctx.xxx is not a function`。
- **上游改了资源加载方式**时注意 `upstream/lib/index.js` 里的 `PACKAGE_ROOT`
  （`lib/index.js` → 上一级即插件包的 `assets/`）；只要上游保持 `lib/` + `assets/`
  的相对结构，本移植就不用动。
- `upstream/` 下的美术素材不在 MIT 覆盖范围内（见 `upstream/PROVENANCE.md`），
  上游若替换素材，直接跟随即可。
